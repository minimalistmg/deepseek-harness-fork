# @deepseek-ai/dsh-client-ui-holds

[English](README.md) | 中文

## 概述

本包用于暂存用户还没准备好发送的输入框草稿。**暂存（Hold）** 控件把当前草稿存入当前会话并清空输入框；输入框卡片上方的暂存区列出已暂存的内容，每一行都可以发送、编辑、删除或调整顺序。DeepSeek 自身的队列仍然是发送通道——暂存草稿是尚未发送的草稿，发送时它会回到输入框再走一次提交流程，因此投递路径不变。暂存内容是按会话保存的浏览器状态：在草稿被恢复并发送之前，这里不会有任何内容进入模型可见范围。

<a id="use-this-package"></a>
## 使用本包

将本插件与 `ui-conversation` 一起挂载；暂存控件会出现在输入框左侧工具行，暂存区显示在输入框卡片上方、发送队列下方。

### 控件行为

| 控件 | 行为 |
|---|---|
| **暂存（Hold）** | 将草稿存入当前会话并清空输入框。正在编辑某条暂存内容时，暂存会把输入框内容写回该条，而不会新增一条。 |
| **发送** | 将暂存文本写入输入框并按常规路径提交，然后删除该行。 |
| **编辑** | 将暂存文本写入输入框，并把该行标记为编辑中。 |
| **删除** | 删除该行。 |
| 调整顺序 | 将一行拖到另一行上，或聚焦该行的拖动把手后按上下方向键。 |

草稿带有附件时、或草稿为空时，暂存会被拒绝，控件提示会说明原因。每个会话只显示自己的暂存内容；本浏览器从未暂存过的会话从空列表开始。

### 失败情形

暂存被拒绝时输入框保持不变。Host 拒绝提交时，提示通过输入框自身的通知显示，与手动输入的消息完全相同；此时该行已经消失，因为暂存区本身不保存任何在途状态。

<a id="understand-the-implementation"></a>
## 了解实现

<details>
<summary>实现细节 —— 点击展开</summary>

插件注册两个座位，它们共享同一个用 `defineStore` 声明的按会话 store：`conversation.input.left` 承载暂存控件，`conversation.input.dock` 承载暂存区。同一个 handle 传给两处注册，正是它们操作同一批草稿的原因；框架按 handle × scope 生成实例，因此持久化键就是 store 自身的键加上会话 id，会话的暂存内容在刷新后依然存在，无需插件自有的文件或 Host 路由。

控件通过会话标准 `useInput` hook 读取草稿，并通过公开的 `inputActions` 面写入：暂存会调用声明的 `hold` 或 `update` 动作，然后调用 `setDraft('')`。它读取 `attachmentIds`，以便在草稿带有浏览器持有的附件时拒绝暂存——暂存值是文本，若清空输入框，这些文件就会被丢弃且无从恢复。引用 chip 以剪贴板文本形式暂存，这正是 `InputState.draft` 的投影。

暂存区只通过 `inputActions.setDraft` 与 `inputActions.submit` 写入，因此它从不直接与会话交互：发送就是一次草稿写入加上与输入框自身 Send 相同的提交，命令声明或忙碌会话都在输入状态机内部解决。调整顺序是同一个操作、两种手势——指针拖拽，以及在聚焦把手上的方向键——因为只能拖拽的控件在没有指针时无法使用。

</details>

<a id="model-experience"></a>
## 模型体验

无，暂存草稿是尚未提交的浏览器文本，只有用户经常规输入框提交发送它时才会到达模型。

#### KV Cache 影响

无。暂存、编辑或删除草稿都不会改变请求前缀；前缀在暂存消息被发送时移动，与手动输入消息完全一样。

## 已知限制与后续工作

<a id="known-limitations-and-deferred-work"></a>


这些限制界定了当前的暂存区。它们是当前的包约束，而不是队列对比或任务清单。

- **仅支持文本** —— 带附件的草稿无法暂存，因此想暂存带文件消息的用户必须先发送或先移除附件。
- **引用 chip 会被展平** —— 暂存草稿保留引用的剪贴板文本而不是 chip；恢复时这段文本会作为纯文本写回。
- **仅限本浏览器** —— 暂存内容保存在本浏览器、针对单个会话。其他浏览器、其他机器或清除站点数据后都看不到它们。
- **一次只能编辑一条** —— 编辑标记按会话保存，从输入框发起新的暂存会清除它。
