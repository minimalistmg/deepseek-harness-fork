# Agent Note: 听写手势与口述文本管线

Status: implemented

[English](2026-09-14-voice-dictation-gestures-and-cleanup.md) | 中文

## Problem

[语音听写座位](2026-09-14-voice-dictation-composer-seat.zh.md) 只在点击麦克风按钮期间听写，并原样插入服务方确认的文本。由此产生三个缺口。双手都在键盘上的用户无法在不使用指针的情况下开始或结束。口述只在用户主动结束时结束，因此免提听写在安静的房间里会一直保持打开。转写文本以服务方听到的样子进入草稿——没有标点、带着说话人的口头语、标识符按读音而非写法拼写——用户必须先修改再发送，而这正是听写本应省去的工作。

该座位也没有偏好设置界面。`conversation.input.right` 的占用者只得到公开的 `inputActions` 面、`useInput` 快照与自己的 inject 面；这套工具中没有任何东西承载持久的用户选择，而 host config 只能到达插件，无法影响浏览器半部的行为。

## Decision

新增按住说话、静默门限、四向口述结束、口述文本管线与持久化的 `ui-voice` 设置分区，并在输入框卡片下方渲染本次口述的音量。

### 手势与结束

控件在 `document` 上以捕获阶段监听 `keydown` 与 `keyup`，绑定一个组合键（默认 `Alt+V`，可配置，留空即禁用）。监听器按绑定只注册一次，并通过 ref 调用当前闭包，因此口述过程中的任何一次渲染都不会重新注册它们。按住产生的按键重复会被忽略；无论先松开字母键还是修饰键，松开都会结束该次口述，因为先松开 `Alt` 再松开 `V` 的用户同样已经完成了手势。

一次口述现在有四种结束方式——按钮、松开按住说话键、静默门限、组件卸载——并携带结束原因。松开按住说话键与静默分别以 `'ptt'` 与 `'silence'` 结束，它们是仅有的两种会自行发送已确认草稿的手势；点击则把草稿留下供检查，因为点击正是用户停下来查看识别结果的方式。

静默门限读取麦克风电平而不是转写文本：服务方只有在听到之后才会报告词句，因此最后一个词之后的安静只体现在电平上。每个采集分片携带其均方根电平，门限在听到说话之前不会报告，且每次口述最多报告一次，因此安静房间里打开的麦克风会继续聆听，而不会在说话人开口前就结束。

### 管线

每段已确认的转写依次经过：口述发送指令、三步文本改写、宿主整理。发送指令先被剥离，因此口述的「send it」不会作为词句残留；改写先于宿主整理运行，因此没有整理凭据的部署同样能得到带标点、无口头语的草稿。三步改写分别是口述标点、口头语与结巴重复、口述大小写提示（`user id in camel case` → `userId`）。

### 偏好设置

宿主设置文档中的 `ui-voice` 分区保存按住说话绑定、自动发送开关、静默时长，以及整理与口述发送开关。宿主半部注册 schema，浏览器半部绑定同一分区，没有设置提供方的部署沿用策略自带的 schema 默认值。解析后的偏好在每次设置变更时计算一次，而不是每次按键都计算。

### 音量条

每个插件实例一个快照 store，保存录音标志与最近的电平。座位写入它；`conversation.composer.dock` 中的第二个注册在输入框卡片下方渲染它。两个入口共享传给两处注册的 handle，这是两个入口读取同一事实的规范做法。

## Alternatives considered

**由桌面壳注册全局快捷键。** 本次改动中否决：Web GUI 才是产品表面，浏览器半部持有的组合键在所有部署中都可用，包括没有 Electron 壳的部署。桌面壳日后可以添加进程级快捷键，而无需改变这一约定。

**为组合键增加输入框键盘面。** 否决：该座位按设计不接收键盘面，而且[先前的座位决策](2026-09-14-voice-dictation-composer-seat.zh.md)已经确定，为输入框呈现问题拓宽 provide 通道需要一个无法使用私有面的消费者。页面级监听器正是该消费者自己的机制。

**在任何结束时都发送。** 否决：点击停止的用户正在检查识别结果，此时发送会把草稿从他眼前拿走。松开与静默才是表示「完成」的手势。

**从转写时间戳判断静默。** 否决：等待服务方报告安静区间需要服务方真的报告，而电平本来就已经在链路上供音量条使用。

**只在宿主侧整理。** 否决：整理按设计是尽力而为的，部署总是能运行的改写不应依赖模型调用。宿主整理仍然保留，因为它能修正确定性改写无法处理的部分——语法、更清晰的表述、口述的文件名。

**用模块级变量缓存解析后的偏好。** 否决：该值属于宿主文档，而宿主文档可能在插件运行期间变化，模块级缓存会活得比拥有它的插件实例更久。

## Consequences

听写现在有键盘手势，因此在每个组合了该座位的页面中 `Alt+V` 都被占用；需要该组合键的部署应改绑或清空它。自动发送可能发送用户尚未阅读的消息，这正是它只对两种表示口述已完成的手势默认开启、并且仍然是偏好的原因。

管线是对单段转写的确定性文本改写，这也是口述标识符提示采用贪婪匹配的原因：提示会转换其前面所有能组成标识符的词，`make the user id in camel case` 会变成 `makeTheUserId`。该限制写在包 README 中，而不是用启发式规则去静默丢弃说话人真正说过的词。

设置分区保存的是绑定字符串而不是解析后的组合键，因此无法解析的值会禁用该手势，而不会让插件加载失败。覆盖率验证了管线的改写、绑定解析器、门限计时、座位的四种结束方式、音量条 store、音量条渲染，以及设置行的提交与拒绝。
