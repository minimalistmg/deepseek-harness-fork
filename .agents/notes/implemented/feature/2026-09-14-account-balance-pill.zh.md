# Agent Note: 以宿主路由支撑的浏览器插件读取带凭据的账户余额

Status: implemented

[English](2026-09-14-account-balance-pill.md) | 中文

## Problem

输入框底部已经在报告单个会话消耗了什么——轮次、步骤、token、缓存命中——这些来自浏览器自行计算的持久投影。它无法报告的是账户还剩多少，因为该读取需要平台 API 密钥，因此需要浏览器不能发出的请求。

想要展示它的插件面临两个问题：由哪一半发起带凭据的调用，以及浏览器半部随后可以如何描述失败。答案与语音插件不同：语音插件的远程调用按设计是尽力而为的，因为用户自己的话已经在手。而这里的读取本身就是功能。

## Decision

新增 `@deepseek-ai/dsh-client-ui-balance`：宿主半部在一个 Connection Fetch 路由背后读取 DeepSeek 平台余额，浏览器半部把它渲染为输入框底部行中的胶囊。

### 传输

宿主在 `/api/account/balance` 注册一个精确的 Connection Fetch 路由，方式为缓冲 `GET`，与语音插件注册其路由的方式相同。浏览器只知道路径与信封；密钥从不离开宿主，单次一元读取也不值得引入 Typert Remote 命名空间。

### 读取

`src/balance.ts` 负责平台调用。密钥放在 `Authorization` 头中，因此任何密钥都不会出现在 URL 里；请求设置 `redirect: 'error'`，因此带凭据的请求绝不会跟随跳转到其他源；一个 `deadline(signal, timeoutMs, …)` 把调用方取消与请求截止时间融合在一起。`timeoutOf` 会把截止时间读回来，因此超出自身截止时间的读取会被报告为超时，而不是传输故障。

结果是可辨识联合——余额，或取代它的结果——而不是可选报告，因此路由不可能在没有报告的情况下序列化出成功。

### 显示币种

配置了显示币种时，会向配置的汇率源站发出第二个请求来换算金额。换算是尽力而为的，与语音插件的整理相同：汇率被拒绝、无法访问或不可用时，余额会保留账户自身币种，而不会把整次读取变成失败。余额才是用户要的东西，换算只是便利。

### 浏览器状态

浏览器把一个信封映射为四种状态。没有凭据的部署报告 `unavailable`，胶囊不渲染任何内容：永远无法填充的胶囊在每个输入框中都是噪音。读取失败会保留一个提供重试的胶囊，因为这是用户可以处理的状态。第一个答案到达之前不渲染任何内容，因此底部不会闪现占位符。

## Alternatives considered

**在浏览器中读取余额。** 直接否决：浏览器持有的任何密钥都可被页面读取，而部署的 `.env` 不是浏览器该读的。

**新增 Typert Remote 命名空间。** 否决：在既有通道上做一次一元读取，不足以支撑一个 Remote、其生成的客户端以及拆分编译器面。语音插件对其缓冲路由得出了相同结论。

**在宿主侧缓存读取结果。** 否决：缓存是带有自身失效问题的状态，而胶囊每次挂载读取一次、每次重试读取一次。需要限制平台流量的部署可以在前面放一个代理，该请求本身已经遵循代理策略。

**只要插件被挂载就显示胶囊。** 否决：在没有 DeepSeek 账户的部署中，胶囊要么空着，要么报告故障，而那是底部最常见的情形。读取缺失就是缺失，不是故障。

**汇率服务失败时让整次读取失败。** 否决：换算不是用户要的东西。

**无条件显示每个额度项。** 否决：赠送与充值额度通常正好合计为总额，重复表头的行没有信息量。只有当某个额度项确实是余额的一部分时才显示它。

## Consequences

底部现在带有一个依赖外部服务的读数，因此没有凭据或没有网络的部署要么不显示，要么显示重试，并且不能把该胶囊当作会话统计来读。每次挂载与每次重试都会读取平台一次，因此打开多个标签页就会读取多次。

覆盖率验证了请求映射与密钥所在的请求头、每个失败分支（含无配额的超时与不可解析的响应体）、换算的降级行为、路由的方法校验与信封、浏览器的四种状态、胶囊的渲染与重试，以及经由已安装代理策略的出站流量。
